# ADR-0035: Sourcing Admission Timestamp Authority

## Status

Accepted (CR-0B1)

## Context

The CR-0B command exposed a caller-owned `requested_at`, but the Application
copied it into both Product Match `verified_at` and Founder Sourcing Admission
`admitted_at`. Production admission needs to preserve factual operator time
without allowing a caller to assert the time at which HYB created its
authoritative Admission. Generating a server time before replay lookup would
also change an otherwise identical command fingerprint and break response-loss
replay.

## Decision

- `requested_at` is the caller-owned time at which the sourcing command was
  created or requested.
- `verified_at` is the caller/operator-owned factual time at which the selling
  Product to sourcing Product match was verified.
- `admitted_at` is generated by an injected server admission clock only on a
  fresh command path.
- `committed_at` is generated independently by the existing injected receipt
  clock only on a fresh command path.
- The immutable Admission preserves both `requested_at` and `admitted_at`.
- The canonical command fingerprint contains caller-controlled command facts,
  including `requested_at` and `verified_at`, but excludes both server clocks
  and all generated identities.
- Repository replay lookup occurs before any identity supplier, admission
  clock, or receipt clock is called. Exact replay returns persisted timestamps.
- Quote revisions follow the same timestamp ownership and replay ordering.

The Admission schema advances to `founder-sourcing-admission-v2`. Persisted v1
rows are not silently reinterpreted because their requested/admitted authority
cannot be reconstructed without inference.

## Consequences

Concurrent fresh attempts may generate losing transient values before SQLite
serialization, but only the winning transaction becomes authoritative. A loser
converges on the committed Admission or reports a changed-payload conflict.
Clock values created before a failed persistence attempt remain non-authoritative
because the transaction writes no partial fact.

## Deferred

FastAPI composition, Founder UI, supplier integration, supplier deduplication,
Economics, Capital Readiness, and Capital Gate remain outside this decision.
