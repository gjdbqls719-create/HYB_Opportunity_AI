HYB Engineering Constitution
전문 (Preamble)

HYB Opportunity AI는 단순히 기능을 빠르게 개발하는 프로젝트가 아니다.

우리는 온라인 판매자가 더 나은 사업 의사결정을 내릴 수 있도록 지원하는 Opportunity Discovery Platform을 구축한다.

따라서 우리의 엔지니어링은 기능 추가 자체보다 신뢰성, 유지보수성, 확장성 그리고 장기적인 제품 가치를 우선한다.

이 문서는 HYB 프로젝트의 모든 엔지니어링 활동에 대한 최상위 기준을 정의한다.

모든 개발자와 AI는 본 문서를 기준으로 설계하고, 구현하고, 테스트하며, 문서를 관리한다.

본 문서와 충돌하는 기술적 결정은 원칙적으로 허용되지 않는다.

예외가 필요한 경우에는 ADR(Architecture Decision Record)를 통해 근거와 영향을 명확히 기록하고 승인받아야 한다.

제8조 Architecture First

Architecture Review는 가치가 있을 때 수행한다.

사소한 기능마다 새로운 아키텍처를 만드는 것은 지양한다.

비즈니스 규칙은 외부 구현으로부터 독립적이어야 한다.

제5장 문서 원칙
제18조 문서는 프로젝트 자산이다.

문서는 코드와 동일한 중요도를 가진다.

문서가 없는 기능은 완료된 기능으로 인정하지 않는다.

제19조 구현과 문서의 동시성

기능이 변경되면 관련 문서도 함께 변경한다.

문서 업데이트를 다음 Sprint로 미루지 않는다.

제20조 단일 책임

동일한 내용을 여러 문서에서 정의하지 않는다.

필요한 경우 참조만 사용한다.

제6장 테스트 원칙
제23조 테스트 우선 원칙

HYB의 모든 기능은 검증 가능한 형태로 구현되어야 한다.

구현만 완료되고 검증되지 않은 기능은 완료된 기능으로 인정하지 않는다.

제24조 기능 테스트 우선

새로운 기능을 구현한 경우 해당 기능에 대한 테스트를 가장 먼저 수행한다.

기능 테스트를 통과하지 못한 상태에서 전체 회귀 테스트만 수행하는 것은 허용하지 않는다.

권장 순서는 다음과 같다.

기능 구현
기능 테스트
버그 수정
기능 테스트 재실행
전체 회귀 테스트
제25조 회귀 테스트

기능 테스트가 완료되면 프로젝트 전체에 대한 회귀 테스트를 수행한다.

회귀 테스트의 목적은 새로운 변경이 기존 기능에 영향을 주지 않았음을 검증하는 것이다.

제26조 테스트 자동화

반복적으로 수행되는 테스트는 가능한 자동화한다.

자동화는 테스트의 신뢰성과 재현성을 높이기 위한 수단이며, 단순한 편의를 위한 것이 아니다.

제27조 실패 기록

테스트가 실패한 경우 원인을 분석하고 기록한다.

동일한 문제가 반복되지 않도록 수정 내용과 원인을 함께 남긴다.

제28조 테스트 품질

테스트는 단순히 성공 여부를 확인하는 것이 아니라 시스템의 동작을 검증해야 한다.

다음과 같은 테스트는 지양한다.

유지보수가 어려운 테스트

모든 리뷰는 문제 해결과 지식 공유를 목표로 한다.

제31조 근거 기반 의견

리뷰 의견은 반드시 근거를 포함한다.

개인의 취향이나 선호만으로 변경을 요구하지 않는다.

필요한 경우 관련 문서, ADR, 테스트 결과 또는 실제 코드를 근거로 제시한다.

제32조 대안 제시

문제를 지적하는 경우 가능한 해결 방안도 함께 제안한다.

리뷰는 비판이 아니라 프로젝트 개선을 위한 협업 과정이다.

제11장 기술 부채 관리
제45조 기술 부채의 정의

기술 부채는 현재의 개발 속도를 높이기 위해 미래의 유지보수 비용을 증가시키는 모든 요소를 의미한다.

기술 부채 자체는 금지하지 않는다.

다만, 기술 부채는 반드시 인지하고 관리해야 하는 대상으로 간주한다.

제59조 개정 원칙

본 문서는 프로젝트의 성장에 따라 개정될 수 있다.

다만, 개정은 프로젝트의 핵심 철학과 장기적인 방향성을 훼손해서는 안 된다.

제60조 개정 승인

본 문서의 개정은 Product Owner의 승인 후 적용한다.

필요한 경우 관련 ADR 및 Foundation 문서를 함께 갱신한다.

부록 A. 핵심 용어

Architecture Review
구현 전에 설계의 적합성을 검토하는 과정.

ADR (Architecture Decision Record)
주요 아키텍처 의사결정의 근거와 결과를 기록하는 문서.

Feature Test
새롭게 구현한 기능이 요구사항대로 동작하는지 검증하는 테스트.

Regression Test
새로운 변경이 기존 기능에 영향을 주지 않았는지 확인하는 테스트.

Sprint
명확한 목표를 가진 반복 개발 단위.

Pull Request
변경 사항을 검토하고 병합하기 위한 공식 개발 단위.

부칙

본 문서는 HYB Opportunity AI의 엔지니어링 활동을 위한 최상위 기준 문서이다.

모든 개발자와 AI는 본 문서를 기반으로 설계, 구현, 테스트, 문서화 및 협업을 수행한다.

본 문서에서 정의하지 않은 사항은 관련 Foundation 문서와 ADR을 참고하며, 최종 판단은 Product Owner의 승인에 따른다.
